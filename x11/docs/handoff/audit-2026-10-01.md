## Ship together, after device tests

Nothing below is published. Each needs a version bump, then a device smoke test.

- **ioscd and Xios must ship together.** Non-root `SESSION app` now takes a desktop-file id, and
  ioscd resolves it to a trusted, root-owned entry. The picker sends that id instead of the
  `Exec=` text. A new ioscd with an old Xios, or the reverse, breaks picker launches.
- **Packages to bump:**
  - com.max.xios and IOSCHost (MARKETING_VERSION)
  - iosc
  - iosc-shell (0.9.13 or later is already in use)
  - xios-launcher-tools / xios-session (ioscd)
  - libmutter-14-0
  - xios-session-stubs, xios-a11y-tools, xios-fhs
  - waybar, angle, basu, kf6-i18n
  - KitchenHub, KioskMode, XiosPrefs
- **About 70 recipes** are older than the published repo, so their next rebuild must go to
  `+ios3`. The list is in `linux-build-extras/versions.txt`.
- **457 of 621 published packages carry no MinimumOSVersion.** The `stamp-minos.py --apply`
  sweep does not appear to run before publishing.

## What the device tests must cover

Step lists are in each follow-up ledger. The behaviour changes worth knowing first:

- **Shell launches** from the dock, overview, pins and "Open Documents" now run as `mobile`, like
  ioscd's LAUNCH. HOME is `/var/mobile`, so apps start with first-run settings. A pin whose
  command needs root now fails.
- **Picker launches** still run under each flavor's existing session identity, which is root.
  Only the free-form text path is closed.
- **GNOME:**
  - Wayland apps get real keycodes.
  - Shell entries and keybindings see modifiers.
  - Soft-keyboard emoji and accents arrive.
  - A Cmd tap opens the overview, and Return carries `\r`.
- **iosc:**
  - When an input client drops, its held buttons, keys, touches and pencil are released.
  - Native windows go dark and stay untitled while locked.
  - The viewporter source rect is in surface-local units, so check mpv's crop.

## Needs a decision

- **a11y bridge and hardware helpers.** These run as root on the `mobile`-owned ioscd bus, and
  dbus-daemon may refuse them, so Home Screen apps could lose UPower, Solid and AT-SPI. Check on
  the device first, then either allow root on that bus or run the helpers as `mobile`. The writeup
  is in `fu-launch.md`.
- **iosc native mode:** the session-lock surface has no canvas, so it is invisible.
- **iosc output size cap:** the output bound still allows 16384×16384.
- **iosc buffer transforms:** iosc ignores `set_buffer_transform` everywhere.
- **Xios:**
  - what to do when the display picker selects a slot that isn't ready;
  - `x11-server.sh` overwrites the live `xios.json`;
  - whether to pause the 20 Hz pump in the background.
- **Shell writes:** they refuse a symlinked last path component only, not a redirected
  `/var/mobile/Library`.

## Smaller leftovers

  threads it never joins. This is the same pattern 0e809c0f fixed in the canvas server. It only
  matters for a server restart.
- linux-build:
  - about 30 lanes pass `CC=`/`CXX=` on the make command line;
  - relink failures are swallowed with `|| true`;
  - `run-target-script.sh` lacks some mounts.

  All three are judgment calls (`linux-build.md`).
