## Needs a decision

- **mobile to root.** Three paths let any `mobile` process act as root, which contradicts the
  ioscd rule that socket clients cannot supply executable text:
  - ioscd `SESSION<TAB>app<TAB><text>` runs `<text>` as root through xios-session's
    `bash -lc "exec ..."`. The Xios picker sends raw `Exec=` lines this way, so picker
    launches also run as root.
  - ioscbg runs pin commands as root via `sh -lc`, and the pins file is `mobile`-writable.
  - iosc-input.sock and the IMPROXY role are open to any `mobile` process, which can inject keys
    into root apps or read iOS keyboard text.

  Proposed fix: the picker sends an app id over `LAUNCH_CLASSIC`, ioscd refuses free-form
  `app` text from non-root peers, and shell or picker launches run as `mobile`. This needs a
  device test. See `session-desktop.md` F1, `iosc-shell.md` #1, `iosc-core.md` #12.
- **Package templates vs package dirs.** The `x11/packages/templates` copies of xios-fhs (1.0.1),
  xios-desktop-theme and xios-session-stubs have drifted. A template build of xios-fhs
  would collide with the published 1.0.1. Pick the source of truth (`packaging.md` #2).
- **`xmkdeb --minos` is a no-op.** It points at a nonexistent path, and stamp-minos works on
  all of `out/` at once. Wire it up or remove it (`packaging.md` #1).

## Needs a build and the device

- **GNOME typing.** `meta-virtual-input-device-ios.c` `notify_keyval` sends keycode 0 for every
  hardware key and soft-keyboard character. Shell entries work, but Wayland apps (kgx) likely
  see key 0. Map keysym to keycode via Mutter's keymap. Confirm by typing into kgx under
  `xios-session gnome`.
- **Stuck buttons.** After an input-socket drop, held buttons and keys are never released (iosc
  side) or reset (app side).
- **Xios main-thread blocking.** The clipboard HELLO, large clipboard writes and the broker XPC
  call are all synchronous on the main thread.
- **iosc device test plan.** Eleven steps, in the PR #5 description and in `iosc-core.md`.
