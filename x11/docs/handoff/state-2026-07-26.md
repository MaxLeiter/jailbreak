## Armed footguns

1. **`git HEAD:repo/Packages` still indexes `openssl 3.5.3+ios1` / `libssl3 3.5.3+ios1`.**
   Restoring `repo/` from HEAD and publishing re-ships the shadowing openssl that bricked
   sshd/apt on 07-08. Commit the current tree before any repo restore.

   decision. **Delete them from `out/` before that script is ever run without `--dry-run`.**

   `build_info/libgspell-1-2.control` says `libicu78`. The fresh ICU-78 pair built Jul 19 20:09 was
   overwritten at Jul 20 00:00 by the `webkitgtk-jsc` run's deb-collection sweep. The
   `HAS_PACKAGE_TARGET` guard in `build-gnome.sh` prevents recurrence but landed after the damage.
   Re-collect from `procursus-vol-gtk-calc` before smoking or publishing these.

4. **15 orphaned generated assets** in `repo/{depictions,icons,banners}/` for `libgspell-1-2`,

## Non-obvious risks in the KDE bundle

- **142-deb mass install via `dpkg -i --force-overwrite`**, single invocation, lexicographic glob,
  no ordering, no dry-run, no snapshot step. `--force-overwrite` lets any staged deb silently take
  ownership of another package's files.
- **`qt6-base 6.6.3-5+ios1` is unpublished** — newer than `repo/debs` and `repo/Packages`
  (`-4+ios1`), adds a `libicu74` dep. Because no same-version repo file exists, it is the one
  package the prep script's byte-verification structurally **cannot** check. qt6-base underpins
  every Qt/KDE process.
- **`angle` upgrade has cross-flavor blast radius** — shared EGL/GL stack, affects
  GNOME/GTK/mpv/Ladybird, not just KDE.
- **Bundle pins `iosc 0.9.18`** while the repo has 0.9.20. Device is on 0.9.17, so the bundle
  would install 0.9.18 rather than the version you'd eventually publish.
- **43 KF6/Qt6 debs are at bare upstream versions** (`kf6-config 6.3.0`) vs `+ios1` in `repo/debs`
  — they came from the build volume, not the finalized repo, and lack `MinimumOSVersion` stamps.
  The installer's downgrade guard skips them if the device already has `+ios1`.
