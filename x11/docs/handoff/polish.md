# polish — smaller feature tracks (one agent could own several)

These are the smaller, mostly-landed-or-parked tracks. Each has a wire type or a plan already; grouped here since none is a full-time domain. Split further if you want dedicated owners.

## Touch scroll + gestures (task #20)
- AXIS wire type 9 landed (iosc decode + Xios `sendScroll`, commit 3ebf085; also fixed BTN_LEFT right-click). Mutter half: `notify_scroll_continuous` + AXIS in virtual-input (build10).
- Wire (xios_input_socket.h): AXIS x,y = dx,dy in 1/256 output-px fixed point; code=source(0 finger/1 wheel); state bit0=axis_stop; mods=modifier mask (ctrl = pinch-zoom).
- Current Xios app uses the unified fit transform, so the old stale-fb warning is closed. Open: two-finger scroll feel, long-press right-click, pinch-zoom (ctrl+scroll) end-to-end on-device across iosc and Mutter. Handoff detail: `x11/docs/axis-gestures-handoff.md`.

## Clipboard sync Linux↔iOS (task #18)
- App side and compositor side have both landed on the 32-byte `XMS1` envelope (`XIOS_MSG_CLIPBOARD` 0x04); the old 8-byte clipboard bridge framing is obsolete. Treat this as co-deploy/verify work: Xios.app and iosc must be from the same wire generation. Memory: x11-clipboard-sync.
- Open: on-device bidirectional smoke (UIKit pasteboard -> wl-copy/GTK, wl-copy/GTK -> UIKit pasteboard), large payload behavior, and multi-item/type coverage beyond text.

## Rotation (task #21)
- XIOS_IN_OUTPUT wire type 10 registered (code = wl_output transform; x,y = requested logical WxH). Rotation = resize + present-reconnect.
- Held (per native-bundle) because iosc doesn't reconfigure its output IOSurface on rotation yet — allowing portrait today just letterboxes. Two halves: iosc reconfigure the output surface on rotate (iosc-compositor.md) + Xios update drawableSize/re-fit on orientation change (xios-app.md #6). Xios build is currently landscape-LOCKED (Info.plist). Unlock is coordinated across xios-app + iosc + native-bundle. Plan: `x11/docs/native-feel-plan.md`.

## Native-feel bundle (tasks #22, #23) — volume / dark-mode / haptics
- Wire types 10-13 (OUTPUT/HAPTIC/VOLUME/APPEARANCE) registered. VOLUME(12)+APPEARANCE(13) go to a separate `xios-sysintd` daemon (socket `/var/jb/tmp/xios-sysint.sock`, same framing) so the compositor stays out of audio/theme. `xios-sysintd`, Xios volume/appearance/output senders, and Xios haptic receiver code exist; `run-gnome-shell.sh` starts `xios-sysintd` when installed. Remaining compositor-side work: handle OUTPUT(10) in iosc for rotation/reconfigure and broadcast HAPTIC(11) to input clients. (A volume HUD was seen working on-device.) Plan: `x11/docs/native-feel-plan.md`. Memory: x11-native-feel-bundle.

## AT-SPI → VoiceOver a11y bridge
- Design committed `x11/docs/a11y-plan.md`; native-flavor half `x11/docs/native-ipados-a11y.md` has the HostA11y publisher prototype wired to send `bind{appid,exec}` and a smoke-only `/var/jb/tmp/xios-a11y-force` enable gate. Wire schema is the authoritative NDJSON schema in that doc. Shipped Linux-side P0/P1 smoke slices: `xios-session_1.0.9`/ioscd launch paths support opt-in `XIOS_ENABLE_A11Y=1` or force-file a11y, start `at-spi-bus-launcher`, write `IsEnabled` + `ScreenReaderEnabled` true, auto-start `xios-a11yd` when installed, avoid duplicate daemon starts, and kill the daemon on session switch; `xios-a11y-tools_0.2.12` installs `atspi-dump` and the snapshot daemon with `/var/jb/tmp/xios-a11y.sock` owned `mobile:mobile` mode 0660 for UIKit hosts. On-device smoke saw `application name="kgx"` / frame `iosc-kgx` on the AT-SPI bus, then socket clients received `hello`/`reset`/`window`/`upsert`; `bind{appid:"org.gnome.Console",exec:"kgx"}` published kgx and a non-matching bind published no windows. Forced native Console smoke then had HostA11y connect, bind, attach scene 3, and publish 12 elements onto the host view. The helper still polls but suppresses unchanged reset/tree republishes and now line-buffers app commands as NDJSON with exact `t` dispatch; split-write smoke across `bind`/`enable` still returned 12 upserts and `actions:["overview.open"]`. It routes `activate`/custom `action` requests to AT-SPI Action.DoAction for published node ids, with synthetic-tap fallback for activate-without-action; `adjust` now routes to AT-SPI Value.SetCurrentValue; snapshots publish AT-SPI value text/current values, state-derived traits/values, and polling-based `focus` messages when AT-SPI exposes a focused node. `atspi-dump` now prints states, action names, and value ranges directly for future smokes; `0.2.12` device dump against Calculator printed frame states including `active`, `sensitive`, `showing`, and `visible`. `0.2.8` device dump printed kgx frame actions including `win.new-tab`/`window.close` and panel action `overview.open`. Direct `0.2.6` probe saw kgx node `1003` expose `actions:["overview.open"]`; stable `0.2.7` Console smoke still published 12 nodes with no socket close but no value-bearing nodes. A fresh native Calculator smoke published 18 elements and one action-rich node, but labels were empty and roles were mostly panel/grouping, so full GTK widget semantics remain open. Real VoiceOver action/adjust gestures are still pending. Default remains `GTK_A11Y=none` unless `XIOS_ENABLE_A11Y=1` or the force file exists. Still open: real VoiceOver gesture validation, full GTK widget tree validation, Qt package/device validation, event-driven focus/action smoke, PID correlation, geometry correlation for desktop Xios, and GTK3/GNOME Shell ATK version-skew fix. Memory: x11-a11y-voiceover-bridge.
